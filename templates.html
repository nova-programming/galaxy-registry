Galaxy Project Templates

The galaxy init command scaffolds complete project structures from templates. Templates provide a consistent layout for your Nova packages — standardized directory structure, manifest, and boilerplate code.

Always start with a template Even if you plan to customize heavily, galaxy init gives you the correct galaxy.json format, .gitignore, and directory conventions. It saves minutes per project and prevents manifest errors when publishing.

Usage

# Create a library
galaxy init library my-lib

# Or just (defaults to library)
galaxy init my-lib

# 'lib' is an alias for 'library'
galaxy init lib my-lib     # same as above

library Template

            
The default template. Creates a reusable Nova module with a standard library layout. Use this for packages you intend to publish to the registry.


            
galaxy init library my-lib
# or simply:
galaxy init my-lib


            
Generated Structure

            
my-lib/
  galaxy.json              # Package manifest (required for all templates)
  src/
    main.nv                # Public API entry point
  tests/
    test_main.nv           # Test scaffold
  README.md                # Documentation placeholder


            
File Descriptions

            

                
FilePurpose

                
galaxy.jsonPackage manifest with name, version, author, license, repository, keywords, dependencies. Auto-filled with sensible defaults.

                
src/main.nvPublic entry point. Importers will access functions via my_lib.function_name(). Contains an empty hello() function as a starting point.

                
tests/test_main.nvBasic test scaffold with a single test function. Run manually via the compiler.

                
README.mdDocumentation template. Fill in what your package does, how to install, and usage examples.

            


            
Example galaxy.json (auto-generated)

            
{
    "name": "my-lib",
    "version": "1.0.0",
    "description": "A Nova library",
    "author": "Your Name",
    "license": "MIT",
    "repository": "yourusername/my-lib",
    "keywords": ["nova", "library"],
    "main": "src/main.nv",
    "dependencies": {}
}


            
Example src/main.nv output

            
# my-lib - A Nova library

def hello() -> string {
    return "Hello from my-lib!"
}




            
            
Customizing Generated Projects

            
After running galaxy init, you should always:


            
    
                
  1. Edit galaxy.json — update author, license, repository (required before publishing)
    2. 
                
  2. Update src/main.nv — replace the placeholder functions with your actual API
    3. 
                
  3. Update README.md — describe your package, usage, and API
    4. 
                
  4. Set up .gitignore — add galaxy_modules/ and any build artifacts
    5. 
            


            

                Before publishing
                The galaxy publish command validates galaxy.json against a strict schema. Missing or incorrect fields will be rejected. Always test with galaxy publish --dry-run if available.
            


            
Adding Files

            
You can add any number of .nv files in src/. The "main" field in galaxy.json specifies the entry point — additional files are imported from there:

            
# src/main.nv
import utils
import math_extras

# Now available as utils.function() and math_extras.function()


            
            
galaxy.json Manifest Reference

            
Every Galaxy package — regardless of template — requires a galaxy.json manifest at the project root. This file is auto-generated by galaxy init.


            

                
FieldRequiredTypeDescription

                
nameYesstringGlobally unique package name. Lowercase, hyphens allowed.

                
versionYesstringSemantic version (e.g., "1.0.0"). Must increase monotonically.

                
descriptionYesstringOne-line summary shown in search results.

                
authorYesstringYour name or GitHub handle.

                
licenseYesstringSPDX identifier (e.g., "MIT", "Apache-2.0").

                
repositoryYesstringGitHub URL in "owner/repo" format.

                
mainNostringEntry point file. Defaults to "src/main.nv".

                
keywordsNoarraySearch tags (e.g., ["http", "networking"]).

                
dependenciesNoobjectPackage name to version constraint map.

            


            
Full Example

            
{
    "name": "nova-http",
    "version": "1.0.0",
    "description": "HTTP client library for Nova",
    "author": "Nova Team",
    "license": "MIT",
    "repository": "nova-programming/nova-http",
    "keywords": ["http", "networking", "client"],
    "main": "src/main.nv",
    "dependencies": {}
}


            
            
Extending the Template System

            
The template system lives in the TEMPLATES dictionary inside _galaxy.py. Each template defines a list of files, their contents, and an optional entry point pattern.


            
Adding a New Template

            
To add your own template, edit the TEMPLATES dict in _galaxy.py:

            
TEMPLATES = {
    "library": {
        "description": "Reusable Nova library",
        "files": {
            "galaxy.json": ...,
            "src/main.nv": ...,
            "tests/test_main.nv": ...,
            "README.md": ...,
        }
    },
    # Add your own:
    "web": {
        "description": "Web application scaffold",
        "files": {
            "galaxy.json": ...
        }
    },
    ...
}


            
Each file entry uses Python's string.Template for variable substitution. Available variables:

            
    
                
  • $name — package name
    • 
                
  • $author — author name
    • 
                
  • $license — license identifier
    • 
            


            

                Template contributions welcome
                If you create a useful template, open a PR to nova-programming/Nova with your addition to TEMPLATES in _galaxy.py.
