Nova Language Documentation

Nova bridges high-level Pythonic simplicity with low-level C-like control. This document provides a complete, detailed architectural guide to all keywords, types, pointer properties, operators, built-in functions, and compiler internals of the Nova language.

1. Flow & Structure Control

  • def: Declares a function. Native codegen generates standard x86 call/ret routines using the cdecl calling convention.
  • class: Defines an object-oriented class template. Methods are compiled with virtual method table (vtable) entry offsets for dynamic dispatch. 
    class Point {
    x: int
    y: int
    def __init__(x_val: int, y_val: int) {
        self.x = x_val
        self.y = y_val
    }
}
  • self: Reference to the current class instance (implicitly passed as the first parameter to methods).
  • import / from / as: Loads external modules or libraries. Circular imports are handled safely. FFI bindings are supported via import "kernel32.dll" as kernel32.
  • if / elif / else: Conditional branching emitting hardware cmp and je/jne instructions.
  • for / while: Supports range loops (for i = 0 to 10 step 1, downto) and collection iterations (for item in list).
  • const: Enforces compile-time variable immutability.
  • null: Evaluates to the memory address 0.

File I/O & Output

  • open(path, mode), read(fd), write(fd, content), close(fd): Standard file operations returning a 32-bit descriptor.
  • print(x): Outputs values invoking type-safe C-level printf equivalents.
  • printd(x): Debug print. Automatically injects the source file line number into the output (e.g., debug - [line 42]: <value>). Only emits assembly if the --debug compiler flag is passed.

2. Built-In Data Types

The static type checker (type_checker.nv) resolves and enforces:

  • int (32-bit signed), float (IEEE-754 32-bit), bool, string, byte, void
  • list[T]: Dynamically-sized array containing elements of type T. Includes aggressive capacity allocation (HeapReAlloc) to prevent linear overhead, and strict bounds-checking to safely terminate out-of-bounds reads.
  • User-defined Structs (data): C-style structs with statically typed fields resolved via 4-byte offsets.

3. Operators

  • Arithmetic: +, -, *, /, % (modulo)
  • Bitwise: & (AND), | (OR), ^ (XOR), ~ (NOT), << (left shift), >> (right shift)
  • Logical: and, or, not (Short-circuiting supported)
  • Structure Check: has (evaluates whether a property field exists on a structure at compile-time)

4. Standard Functions

  • len(var): Returns count of elements. For strings, computes via _strlen loop. For lists, reads capacity fields.
  • str(var): Converts numbers to strings via FFI sprintf.
  • sizeof(var): Evaluates the compile-time byte size of variables.
  • lst.append(value) / lst.pop(): Dynamically modifies list buffers.

5. Native OS Interface

  • sys_get_args(): Extracts CLI arguments via FFI (GetCommandLineA) returning a parsed string array.
  • sys_system(cmd): Executes shell sub-processes.
  • sys_exit(code): Terminates the process immediately.
  • sys_get_tick_count(): Returns system uptime in ms.
  • random(): Returns a cryptographically secure 32-bit random integer using an optimized ChaCha20 block algorithm, auto-seeded at runtime using the tick count.

6. Unsafe & Memory Directives

Nova allows dropping to bare-metal using the @raw { ... } block directive. Inside raw blocks, you gain access to:

  • Inline Assembly: Lines starting with x86 mnemonics are emitted directly.
  • Heap Allocations: alloc(size) and free(ptr) manually manage memory bytes.
  • Symbol Exporting: @export { name1 } exposes global symbols for external linkage.

Pointer Arithmetic

Variables representing memory addresses can be manipulated directly:

  • ptr.value / ptr.value_dword: Read/write 32-bit double-word (4 bytes).
  • ptr.value_word: Read/write 16-bit word (2 bytes).
  • ptr.value_byte: Read/write 8-bit byte.
  • ptr.addr: Returns the raw memory address.
  • ptr.isValid / ptr.isNull: Evaluates if pointer is non-zero or zero.
  • ptr.bytes: Accesses raw byte-level array representations.

7. Compiler Architecture & Optimizations

When running nova_main.exe build, the self-hosted compiler executes in a single pipeline:

  1. lexer.nv: Tokenizes source characters into a stream of structured Token structs.
  2. parser.nv: Constructs a syntax tree (AST) via recursive-descent parsing and performs aggressive constant folding.
  3. type_checker.nv: Infers and validates static types.
  4. codegen.nv: Generates Intel-syntax x86-32 assembly lines. Injects list/array bounds checking and maps variables to esi/edi registers (Variable-to-Register Promotion).
  5. assembler.nv: Encodes assembly to native machine code bytes (in-process).
  6. linker.nv: Packages machine code into a Windows PE binary (GCC-free compilation).

Tree-Shaking Dead Code Elimination: The compiler builds a dependency graph of function calls and slices out unused standard library routines, reducing final binary sizes by up to 70%.

8. CLI Modes

Nova supports multiple modes depending on your target:

  • python main.py build program.nv: Production build (uses GCC).
  • python main.py dev program.nv: Runs instantly in Python VM.
  • nova_main.exe build program.nv: Self-hosted build (No GCC).
  • nova_main.exe assemble-link input.s output.exe: Directly assembles/links raw x86 assembly to PE.
  • nova_main.exe build-bare program.nv <org> <entry>: Flat, headerless binary for bare-metal OS development.
