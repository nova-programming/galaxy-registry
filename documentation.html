Nova Language Documentation

Welcome to the official Nova documentation. Nova is a systems programming language that compiles directly to native machine code (x86, x86_64, etc.) â€” no interpreter, no VM, no gigabytes of build tools. It gives you C-level performance with Python-level readability.

Quick Start

Get a Nova program running in under a minute.

Installation

Download the nova.exe binary from the releases page. Place it anywhere in your PATH. No dependencies required.

Your First Program

Create hello.nv:

print("Hello, World!")

Compile and run:

# Compile to a Windows executable
nova build hello.nv

# Run it
.\hello.exe
No toolchain needed The Nova compiler contains its own lexer, parser, assembler, and linker. Unlike C/Rust, you don't need to install separate tools to compile code.

Why Nova? (The Philosophy)

Developers today face an impossible trade-off: high-level languages (Python, JS) let you iterate fast but run 10-50x slower than C, while low-level languages (C, C++, Rust) give you raw speed but force you through setup hell and manual memory management.

Nova eliminates this compromise.

  • 14x Faster than Python â€” direct native compilation, no interpreter overhead
  • Near-C Performance â€” competes with GCC -O3 on tight integer loops
  • Zero Dependencies â€” a single 200 KB binary is the entire toolchain
  • Pythonic Syntax â€” reads like Python, runs like C
  • Self-Hosted â€” the compiler can compile itself
  • Tree-Shaking â€” dead code elimination shrinks binaries by up to 70%

Comprehensive Syntax Guide (Playground Ready)

Nova is strictly typed via static inference and explicit type annotations. Below is a comprehensive guide to all Nova syntax. All examples can be copied directly into the Playground to test!

1. Variables & Types

def test_variables() {
    # Implicit typing (Inferred)
    name = "Nova"
    age = 1
    is_fast = true
    
    # Explicit typing
    count: int = 10
    pi: float = 3.14159
    message: string = "Hello!"
    
    print(name)
    print(pi)
}
test_variables()

2. Control Flow (If / Elif / Else)

def check_status(code: int) {
    if code == 200 {
        print("Success")
    } elif code == 404 {
        print("Not Found")
    } else {
        print("Unknown Error")
    }
}
check_status(404)

3. Loops (For & While)

Nova provides multiple looping constructs.

def test_loops() {
    # Upward counting
    print("Counting up:")
    for i = 0 to 5 {
        print(i)
    }

    # Downward counting with step
    print("Counting down by 2:")
    for x = 10 downto 0 step 2 {
        print(x)
    }

    # Iterating over a list
    print("List iteration:")
    items = ["A", "B", "C"]
    for item in items {
        print(item)
    }

    # While loops
    print("While loop:")
    count = 0
    while count < 3 {
        print(count)
        count = count + 1
    }
}
test_loops()

4. Switch / Case

Use switch statements for clean multi-branch logic.

def get_name(id: int) -> string {
    switch id {
        case 1: { return "Alice" }
        case 2: { return "Bob" }
        default: { return "Unknown" }
    }
}
print(get_name(1))
print(get_name(99))

5. Data Classes

Define structures using the class keyword.

class Vector2D {
    x: int
    y: int
}

def test_vector() {
    v = Vector2D()
    v.x = 10
    v.y = 20
    print("Vector Sum: ")
    print(v.x + v.y)
}
test_vector()

6. Enums

Define enumerations for state management.

enum State {
    IDLE,
    RUNNING,
    ERROR
}

def test_enum() {
    current = State.RUNNING
    print("Current State (Integer Value):")
    print(current)
}
test_enum()

7. Try / Catch / Throw

Nova supports structured exception handling.

def divide(a: int, b: int) -> int {
    if b == 0 {
        throw "Division by zero!"
    }
    return a / b
}

def test_math() {
    try {
        result = divide(10, 0)
        print(result)
    } catch e {
        print("Error caught: " + e)
    }
}
test_math()

Classes & Objects

Nova supports basic object-oriented programming with classes, fields, and methods. Method calls use vtable dynamic dispatch.

class Player {
    health: int
    name: string

    def __init__(h: int, n: string) {
        self.health = h
        self.name = n
    }

    def take_damage(amount: int) {
        self.health = self.health - amount
    }

    def is_alive() -> bool {
        return self.health > 0
    }
}

# Usage
p = Player(100, "Hero")
p.take_damage(25)
print(p.is_alive())   # true

Galaxy Package Manager

Galaxy is the official package manager for Nova. It is a fully static, Git-backed registry â€” no database, no backend server. The CLI is a single-file Python script (_galaxy.py) that you install once.

Try it now Install galaxy and be up and running in under 30 seconds.

Installing Galaxy CLI

The Galaxy CLI runs as a standalone galaxy command â€” no python -m prefix needed after installation.

One-Click Install (No Python Required)

Windows (PowerShell, pre-installed):

powershell -ExecutionPolicy Bypass -Command "Invoke-WebRequest -Uri https://galaxy-registry.vercel.app/install.ps1 -OutFile install.ps1; powershell -ExecutionPolicy Bypass -File install.ps1"

macOS / Linux (bash):

curl -O https://galaxy-registry.vercel.app/install.sh && bash install.sh

Any platform (requires Python):

curl -O https://galaxy-registry.vercel.app/install.py && python install.py

On Windows without curl:

Invoke-WebRequest -Uri https://galaxy-registry.vercel.app/install.py -OutFile install.py; python install.py

The installer does four things:

  • Downloads the Nova compiler (main.py, compiler/, parser/, lexer/, nova_ast/, vm/, stdlib/, modules/, tools/) and Galaxy CLI (_galaxy.py, galaxy/) to %LOCALAPPDATA%\nova\ (Windows) or ~/.nova/ (Unix)
  • Creates nova.bat, galaxy.bat, and use_nova.bat helper (Windows) or shell scripts (Unix) launchers
  • Adds the install directory to your user PATH â€” no admin privileges needed
  • Verifies SHA-256 integrity of the downloaded archive

To use nova and galaxy immediately without restarting your terminal:

# cmd.exe:
call "%LOCALAPPDATA%\nova\use_nova.bat"

# PowerShell:
$env:PATH = "$env:LOCALAPPDATA\nova;$env:PATH"

Or open a new terminal and run:

# Verify installation
nova --version
galaxy --version

Method 2: From Source (if you already cloned the repo)

git clone https://github.com/nova-programming/Nova.git
cd Nova
python install.py

Method 3: Direct (no install, run from repo)

python _galaxy.py --help
# or
python -m galaxy --help

Uninstalling

# Re-run the installer with --uninstall
python install.py --uninstall

galaxy.json Manifest Reference

Every Galaxy package requires a galaxy.json manifest at its root. Auto-generated by galaxy init.

{
    "name": "my-lib",               # Required: package name (globally unique)
    "version": "1.0.0",             # Required: semver
    "description": "...",          # Required: short description
    "author": "Your Name",          # Required
    "license": "MIT",               # Required: SPDX identifier
    "repository": "...",            # Required: GitHub URL (owner/repo)

Publishing a Package

All publishing goes through a GitHub Issue workflow â€” there is no direct write access to the registry. This ensures every submission is reviewed.

Using galaxy publish (Recommended)

  1. Write your Nova library and host it on GitHub
  2. Run galaxy init library my-lib to scaffold the project
  3. Edit galaxy.json â€” set author, repository, license, keywords
  4. Run galaxy publish from the project root

galaxy publish does the following:

  • Validates galaxy.json completeness and correctness
  • Computes SHA-256 hashes of every source file
  • Opens your browser to a pre-filled GitHub Issue on the galaxy-registry repo

What happens after publishing

  1. Your package starts in the Community tier
  2. A human reviewer checks the submission via the GitHub Issue
  3. Once approved, the maintainer creates a PR to add your packages/<name>.json file
  4. Merged = instantly available worldwide via galaxy install <name>

Promotion to Verified

Community packages with 50+ upvotes are automatically queued for promotion review (via GitHub Actions). A maintainer reviews the source code for quality and security. If approved, the package moves to the Verified tier.

Manual submission

You can also submit directly by opening a Pull Request to the galaxy-registry repo with a new package JSON in packages/.

Naming rules Package names are globally unique across all three tiers. Once a name is taken, it cannot be reused. Versions must increase monotonically â€” no downgrades, no repeats.

Import System

Nova uses a simple module system. The import keyword loads another .nv file and makes its public functions available.

// file: math_utils.nv
def double(x: int) -> int {
    return x * 2
}

// file: main.nv
import math_utils

result = math_utils.double(21)   // -> 42

The import system uses module prefixing â€” you call imported functions as module_name.function_name().

Build Modes

  • Release (default): Full optimizations (peephole, leaf-to-reg, setcc). Debug prints are zero-cost.
  • Debug (--debug): Enables printd statements for tracing. Produces slightly larger binaries.
File naming Nova source files use the .nv extension. The compiler outputs an .exe with the same base name as the input file by default.

Python Bridge (Seamless Interop)

Nova features a zero-friction Python Bridge (nova_py.py) that allows you to natively import .nv files directly into Python scripts. The bridge automatically compiles the Nova code into high-speed native assembly (.dll/.so), handles SysV ABI translations, maps C-types to Python types, and binds the functions—all transparently on import.

To use it, just import nova_py once, then import your Nova modules as if they were standard Python modules:

import nova_py
import math_lib # Automatically compiles math_lib.nv and loads it natively!

# Call Nova's C-speed functions natively from Python
result = math_lib.calculate_fibonacci(40)
print(result)
Tip: The Python bridge is perfect for accelerating heavy computational logic in existing Python applications without writing C extensions.

Advanced Features

1. Inline Assembly (@raw Blocks)

Drop directly into native assembly anywhere in your code. This is Nova's escape hatch for low-level optimization and hardware access.

def fast_inv_sqrt(number: float) -> float {
    @raw {
        mov rax, dword [rbp+8]
        shr rax, 1
        mov rcx, 0x5f3759df
        sub rcx, rax
        mov dword [rbp-4], rcx
    }
}

2. Zero-Cost Debug Printing (printd)

The printd keyword acts as a native debug assertion. In release builds, it emits zero assembly instructions. In --debug mode, it prints the line and value.

for i = 0 to 1000000 step 1 {
    # Zero cost in release builds
    printd(i)
}

3. Field Existence Check (has Keyword)

Check at runtime if an object or struct has a field.

class Entity {
    name: string
    score: int
}

def check_score(entity) {
    if entity has score {
        print("Score: " + entity.score)
    }
}

4. CSPRNG (ChaCha20)

Nova embeds a cryptographically secure random number generator. Auto-seeded at startup from the OS tick count.

# Generate a secure random value
salt = random()

# Full ChaCha20 control
state = chacha20_init(key, counter)
block = chacha20_block(state)

5. Pointer Suffix Directives

Read and write arbitrary memory sizes from raw pointer addresses using explicit suffix properties.

def write_header(ptr: int, size: int) {
    ptr.value_dword = size     # Write 4 bytes
    flag = ptr + 4
    flag.value_byte = 1      # Write 1 byte
}

Suffix directives: .value_byte (8-bit), .value_word (16-bit), .value_dword (32-bit).

Native OS Integration

Nova communicates with the host operating system through built-in wrappers. These compile to direct syscall wrappers or C runtime calls.

# Get command-line arguments
args = sys_get_args()
for i = 0 to len(args) step 1 {
    print(args[i])
}

# Execute a shell command
code = sys_system("dir")

# Exit with status code
sys_exit(0)

# Timing
start = sys_get_tick_count()
# ... do work ...
elapsed = sys_get_tick_count() - start
print("Took " + elapsed + " ms")

Compiler Architecture

When you run nova build hello.nv, the compiler processes your source through a single in-process pipeline:

  1. Lexer â€” tokenizes source into structured Token objects
  2. Parser â€” recursive-descent parser that builds an AST with constant folding
  3. Type Checker â€” static type inference and validation
  4. Code Generator â€” emits native assembly (dynamically selected for your target architecture like x86_64, arm64) with bounds-checking and variable-to-register promotion
  5. Tree Shaker â€” builds a call-graph dependency map and removes unused stdlib functions (up to 70% binary size reduction)
  6. Assembler â€” encodes assembly mnemonics to native machine code in-process
  7. Linker â€” packages machine code into a valid Windows PE binary

The entire pipeline runs in a single process. No external tools are invoked.

Self-Hosting

The Nova compiler is self-hosted â€” the compiler can compile its own source code. The Python bootstrap compiler was used to build the first binary, which can then compile all future versions of the compiler written in Nova itself.

Performance Tips

Nova is already fast out of the box, but here are ways to get the most out of it:

  • Prefer local variables â€” Nova maps locals to CPU registers (esi/edi). The fewer memory accesses, the faster your code.
  • Use for loops â€” they compile to tight cmp/jl sequences. Avoid unnecessary function calls inside hot loops.
  • Avoid recursion for deep iterations â€” Nova's function calls have standard call/ret overhead. Use iterative loops for performance-critical paths.
  • Use @raw blocks for hot paths â€” if you know the exact assembly sequence, inline it directly to skip the compiler's generic codegen.
  • Release builds only â€” never ship a debug binary (--debug enables printd which adds overhead).
Benchmarking note In heavy computation benchmarks, Nova runs 14x faster than Python and within 2x of GCC -O3. Integer-heavy loops are the strongest use case.
