Nova Language Documentation

Nova is a systems programming language that bridges high-level Pythonic simplicity with low-level C-like control. It features a fully functional self-hosted compiler pipeline capable of generating native x86 assembly and standalone Windows PE executables without relying on external toolchains like GCC.

Why Nova?

Nova is built for developers who want the rapid iteration speed of Python but the raw metal performance of C.

  • Versus Python: Nova compiles down directly to x86-32 assembly. In heavy computational benchmarks (e.g., recursion, modulo arithmetic), Nova runs 14x faster than Python (104ms vs 1458ms).
  • Versus C/GCC: Nova doesn't require a multi-gigabyte build environment. The entire compiler, assembler, and linker are fully integrated into a single pipeline. It achieves near-C performance (104ms vs GCC's 62ms with -O3) out of the box.

Getting Started

To start building with Nova and using the Galaxy package manager, clone the compiler:

git clone https://github.com/nova-programming/Nova.git
cd Nova

CLI Modes & Flags

Nova is exceptionally flexible. It can run code instantly via a Python VM, or build a bare-metal OS image.

Core Modes

  • python main.py build program.nv: Production - Compiles to native x86 executable using python codegen + GCC.
  • python main.py dev program.nv: Development - Runs instantly in the Python bytecode VM. Great for rapid testing.
  • nova_main.exe build program.nv: Self-hosted - The Nova-compiled compiler compiles your script directly to a native PE executable using its internal assembler and linker (No GCC required).
  • nova_main.exe assemble-link input.s output.exe: Assembler/Linker - Assembles and links a raw x86 assembly file directly to a PE executable.
  • nova_main.exe build-bare program.nv <org> <entry>: Flat Binary - Compiles to a flat, headerless binary without OS imports. Perfect for bootloaders and bare-metal OS development.

Compiler Flags

  • --debug: Enables debug prints. Any printd(x) statement in your code will only be emitted as assembly if this flag is present. It automatically injects the file line number into the output (e.g., debug - [line 42]: <value>).

Unique Optimizations

Nova packs several advanced compiler optimization techniques to ensure lean, blazing-fast binaries.

  • Tree-Shaking Dead Code Elimination: The compiler natively builds a dependency graph of all function calls. It slices out unused standard library functions, reducing final binary sizes by up to 70%. (e.g., A minimal program drops from 11.5 KB to 3.5 KB).
  • Variable-to-Register Promotion: The compiler greedily maps local variables to high-speed CPU registers (esi and edi), drastically minimizing expensive stack memory reads/writes.
  • Native Standard Library Injection: Functions from os_win and math_utils are automatically injected and natively compiled into all executables. No manual imports of core modules required.
  • Automatic CSPRNG Initialization: The built-in random() function uses a highly-optimized ChaCha20 block generation algorithm. It automatically seeds itself at runtime using the host system tick count.

Keywords & Flow Control

  • def: Declares a function. Compiles to standard x86 call/ret routines using the cdecl calling convention (caller cleans the stack).
  • class / data: Defines an object-oriented class template (with vtable virtual dispatch via offset resolution) or a static C-style data structure.
  • import / from / as: Module import system. Galaxy packages and FFI libraries (e.g., import "kernel32.dll" as kernel32) are seamlessly resolved.
  • for: Supports range loops (for i = 0 to 10 step 2, downto) and collection iterations (for item in list).
  • const: Enforces strict compile-time variable immutability.
  • has: Evaluates whether a property field exists on a data structure at compile-time.

Built-in Data Types

The static type checker automatically infers and enforces strict types:

  • int (32-bit signed), float (IEEE-754 32-bit, uses x87 FPU hardware at runtime).
  • bool (Supports short-circuiting and/or evaluation).
  • string (Null-terminated character sequences).
  • list[T]: Dynamically-sized typed arrays. Uses exponential capacity allocation (HeapReAlloc) to prevent linear insertion overhead. Includes bounds-checking instructions (cmp ecx, [edx], jl, jge) on every access to safely terminate out-of-bounds reads.

Unsafe & Memory Directives

Nova allows you to drop down to bare-metal control at any time using the @raw block directive. Everything inside a raw block bypasses safety checks.

@raw {
    mov eax, 42
    push eax
}

Inside raw blocks, you gain access to:

  • Inline Assembly: Lines starting with x86 mnemonics are emitted directly into the assembly pipeline.
  • Symbol Exporting: Use @export { name1 } to expose global symbols for external linkage.
  • Heap Allocations: Call alloc(size) and free(ptr) to manually request and release raw memory bytes.
  • Pointer Arithmetic: Read/write directly to memory addresses using suffixes: ptr.value_dword (4 bytes), ptr.value_word (2 bytes), ptr.value_byte (1 byte). Evaluate memory using ptr.addr, ptr.isValid, and ptr.isNull.

Compiler Architecture

When you run nova_main.exe build, the self-hosted compiler processes your code through a pipeline of internal modules written completely in Nova:

  1. lexer.nv: Tokenizes source characters into structural tokens.
  2. parser.nv: Constructs a syntax tree (AST) via recursive-descent parsing and performs constant folding (e.g., 1+2 becomes 3 at compile-time).
  3. type_checker.nv: Infers and validates static types across all nodes.
  4. codegen.nv: Generates Intel-syntax x86-32 assembly lines, injects array bounds checking, and maps variables to registers.
  5. assembler.nv: Encodes assembly mnemonics into raw native machine code bytes (in-process).
  6. linker.nv: Packages the machine code, imports, and resources into a valid Windows PE binary natively.
