Nova Language Documentation

Welcome to the official Nova documentation. Nova is a systems programming language that compiles directly to x86 machine code — no interpreter, no VM, no gigabytes of build tools. It gives you C-level performance with Python-level readability.

Quick Start

Get a Nova program running in under a minute.

Installation

Download the nova_main.exe binary from the releases page. Place it anywhere in your PATH. No dependencies required.

Your First Program

Create hello.nv:

print("Hello, World!")

Compile and run:

# Compile to a Windows executable
nova_main build hello.nv

# Run it
.\hello.exe
No toolchain needed The Nova compiler contains its own lexer, parser, assembler, and linker. Unlike C/Rust, you don't need to install separate tools to compile code.

Why Nova? (The Philosophy)

Developers today face an impossible trade-off: high-level languages (Python, JS) let you iterate fast but run 10-50x slower than C, while low-level languages (C, C++, Rust) give you raw speed but force you through setup hell and manual memory management.

Nova eliminates this compromise.

  • 14x Faster than Python — direct x86 compilation, no interpreter overhead
  • Near-C Performance — competes with GCC -O3 on tight integer loops
  • Zero Dependencies — a single 200 KB binary is the entire toolchain
  • Pythonic Syntax — reads like Python, runs like C
  • Self-Hosted — the compiler can compile itself
  • Tree-Shaking — dead code elimination shrinks binaries by up to 70%

Variables

Variables are declared with name: type = value. Type inference is automatic if you omit the annotation.

# Explicit type annotation
name: string = "Nova"
age: int = 42

# Type inference — Nova figures it out
pi = 3.14          # inferred as float
is_ready = true    # inferred as bool
count = 100        # inferred as int

# Constants (must be initialized at declaration)
const MAX_SIZE = 4096

Basic I/O

print("Hello")               # Print string (with newline)
print(42)                    # Print integer
print(3.14)                  # Print float
print("Value: " + 42)        # Concatenated output

Lists

# Declare and initialize
numbers: list = [1, 2, 3, 4, 5]

# Access elements (bounds-checked at runtime)
first = numbers[0]      # -> 1

# Iterate
for i = 0 to numbers.length step 1 {
    print(numbers[i])
}

# Nested lists
matrix = [[1, 2], [3, 4], [5, 6]]
print(matrix[1][0])  # -> 3
Bounds checking All list accesses are bounds-checked at runtime. An out-of-bounds access triggers a runtime assertion and terminates the program. There is zero overhead for bounds checks in release builds that pass static analysis.

Classes & Objects

Nova supports basic object-oriented programming with classes, fields, and methods. Method calls use vtable dynamic dispatch.

class Player {
    health: int
    name: string

    def __init__(h: int, n: string) {
        self.health = h
        self.name = n
    }

    def take_damage(amount: int) {
        self.health = self.health - amount
    }

    def is_alive() -> bool {
        return self.health > 0
    }
}

# Usage
p = Player(100, "Hero")
p.take_damage(25)
print(p.is_alive())   # true

Galaxy Package Manager

Galaxy is the official package manager for Nova. It is fully Git-backed — there is no central database. Packages are registered via pull requests to the galaxy-registry repository.

Installing a Package

nova galaxy install nova-http
nova galaxy install nova-math

The package source code is downloaded to a local cache and linked at compile time. After installation, you can import it:

import nova_http

response = nova_http.get("https://api.example.com")
print(response)

Listing Available Packages

nova galaxy list

Or browse them on the Galaxy Registry website.

Publishing a Package

  1. Host your Nova library publicly on GitHub
  2. Fork nova-programming/galaxy-registry
  3. Create a JSON file in packages/ (e.g., my-lib.json)
  4. Open a Pull Request

Package metadata format:

{
    "package": "my-lib",
    "github_repo": "yourusername/my-lib",
    "version": "1.0.0",
    "author": "Your Name",
    "description": "Does something awesome.",
    "tags": ["utility", "cli"],
    "download_url": "https://github.com/yourusername/my-lib/archive/refs/heads/main.zip"
}

Once merged, your package is instantly available worldwide via nova galaxy install.

Import System

Nova uses a simple module system. The import keyword loads another .nv file and makes its public functions available.

// file: math_utils.nv
def double(x: int) -> int {
    return x * 2
}

// file: main.nv
import math_utils

result = math_utils.double(21)   // -> 42

The import system uses module prefixing — you call imported functions as module_name.function_name().

Compiler Command-Line Reference

The nova_main.exe binary is the entire compiler and CLI frontend.

CommandDescription
nova_main build <file.nv>Compile a Nova source file to a Windows PE executable
nova_main build --debug <file.nv>Compile with debug output (printd enabled)
nova_main build --output <name> <file.nv>Specify output executable name
nova_main galaxy install <pkg>Install a package from the Galaxy registry
nova_main galaxy listList all available packages
nova_main (no args)Print help and usage information

Build Modes

  • Release (default): Full optimizations (peephole, leaf-to-reg, setcc). Debug prints are zero-cost.
  • Debug (--debug): Enables printd statements for tracing. Produces slightly larger binaries.
File naming Nova source files use the .nv extension. The compiler outputs an .exe with the same base name as the input file by default.

Advanced Features

1. Inline Assembly (@raw Blocks)

Drop directly into x86 assembly anywhere in your code. This is Nova's escape hatch for low-level optimization and hardware access.

def fast_inv_sqrt(number: float) -> float {
    @raw {
        mov eax, dword [ebp+8]
        shr eax, 1
        mov ecx, 0x5f3759df
        sub ecx, eax
        mov dword [ebp-4], ecx
    }
}

2. Zero-Cost Debug Printing (printd)

The printd keyword acts as a native debug assertion. In release builds, it emits zero assembly instructions. In --debug mode, it prints the line and value.

for i = 0 to 1000000 step 1 {
    # Zero cost in release builds
    printd(i)
}

3. Static Duck Typing (has Keyword)

Statically check if a structure has a field at compile time.

def serialize(entity: any) {
    if entity has score {
        print("Score: " + entity.score)
    }
}

4. CSPRNG (ChaCha20)

Nova embeds a cryptographically secure random number generator. Auto-seeded at startup from the OS tick count.

# Generate a secure random value
salt = random()

# Full ChaCha20 control
state = chacha20_init(key, nonce)
block = chacha20_block(state)

5. Pointer Suffix Directives

Read and write arbitrary memory sizes from raw pointer addresses using explicit suffix properties.

def write_header(ptr: int, size: int) {
    ptr.value_dword = size     # Write 4 bytes
    flag = ptr + 4
    flag.value_byte = 1      # Write 1 byte
}

Suffix directives: .value_byte (8-bit), .value_word (16-bit), .value_dword (32-bit).

Native OS Integration

Nova communicates with the host operating system through built-in wrappers. These compile to direct syscall wrappers or C runtime calls.

# Get command-line arguments
args = sys_get_args()
for i = 0 to args.length step 1 {
    print(args[i])
}

# Execute a shell command
code = sys_system("dir")

# Exit with status code
sys_exit(0)

# Timing
start = sys_get_tick_count()
# ... do work ...
elapsed = sys_get_tick_count() - start
print("Took " + elapsed + " ms")

Compiler Architecture

When you run nova_main build hello.nv, the compiler processes your source through a single in-process pipeline:

  1. Lexer — tokenizes source into structured Token objects
  2. Parser — recursive-descent parser that builds an AST with constant folding
  3. Type Checker — static type inference and validation
  4. Code Generator — emits Intel-syntax x86-32 assembly with bounds-checking and variable-to-register promotion
  5. Tree Shaker — builds a call-graph dependency map and removes unused stdlib functions (up to 70% binary size reduction)
  6. Assembler — encodes assembly mnemonics to native x86 machine code in-process
  7. Linker — packages machine code into a valid Windows PE binary

The entire pipeline runs in a single process. No external tools are invoked.

Self-Hosting

The Nova compiler is self-hosted — the compiler can compile its own source code. The Python bootstrap compiler was used to build the first binary, which can then compile all future versions of the compiler written in Nova itself.

Performance Tips

Nova is already fast out of the box, but here are ways to get the most out of it:

  • Prefer local variables — Nova maps locals to CPU registers (esi/edi). The fewer memory accesses, the faster your code.
  • Use for loops — they compile to tight cmp/jl sequences. Avoid unnecessary function calls inside hot loops.
  • Avoid recursion for deep iterations — Nova's function calls have standard call/ret overhead. Use iterative loops for performance-critical paths.
  • Use @raw blocks for hot paths — if you know the exact assembly sequence, inline it directly to skip the compiler's generic codegen.
  • Release builds only — never ship a debug binary (--debug enables printd which adds overhead).
Benchmarking note In heavy computation benchmarks, Nova runs 14x faster than Python and within 2x of GCC -O3. Integer-heavy loops are the strongest use case.
